# Codex 接入检查与修复

2026-11-08 当前实现：新任务通过客户端本机 `create_thread` / `send_message_to_thread` 直接执行，目标可使用 `list_projects` 的原生项目编号，也可不指定项目。执行沿用客户端权限，不传网络、沙箱或审批覆盖值；模型与推理强度默认沿用客户端，仅在任务明确选择时传入。运行中的原对话可直接打开，无需停止并交回。

豆包、WorkBuddy 和 Codex 共用定时任务面板，支持每次新建或复用任务对话、每次运行记录、通知策略和成功记录归档。调度、日期输入和显示跟随电脑本地时间与时区，兼容旧计划并覆盖夏令时。171 项主程序回归及桌面、窄屏交互验证通过。

工作台保存发送检查点、实际对话与轮次编号；重启仅恢复该轮次的观察，发送结果不明时不自动重发。停止监控和超时均保留客户端执行，暂停工作台接续。旧项目编号读取别名后转换，已有对话在发送前重新核对项目归属。

验证：146 项主程序回归通过；真实调度器创建客户端项目新对话，观察到客户端 active 状态、完成固定回复并核对侧栏原生项目 ID，完成后归档测试对话。测试没有调用独立执行器，也没有传入权限或模型覆盖。

以下为此前过渡实现的检查记录；其中“独立执行后释放”“自动分配侧栏”和“继承 config/read 权限”的路径仅用于旧运行兼容，不是新任务的执行方式。

本次修复以本机 Codex 生成的协议 Schema、客户端原生项目工具、实际接口及回归测试为依据。

后续核验确认：仅写入 app-server 的项目 ID 并不保证桌面侧栏归属，原实现还覆盖了客户端自动审批和网络配置。以下补正已部署。

- 权限直接继承目标项目的 `config/read` 与客户端选中的审批模式，不再使用面板中的模型、审批、文件权限或网络覆盖值。界面仅保留运行时间和错过预约处理。
- 创建使用可立即读取的分页持久化历史；发送第一条提示词之前，通过客户端现有本机工具接口完成项目分配并确认结果。后台与桌面项目编号分别匹配，不改写客户端全局状态文件。
- 客户端项目同步失败时，运行失败并保留错误，不发送模型任务。临时导入新对话所需的侧栏注册会恢复原置顶状态。
- 已通过真实工作台调度链路验证：自动新建、客户端项目确认、自动审批、继承联网与模型配置；测试拦截模型请求并归档验证对话，没有运行模型任务。
- 主程序当前 140 项回归测试通过。旧的人工审批轮次已停止并保留记录，未重发原任务，队列保持暂停。

- 项目归属：工作目录不等于客户端项目。通过 `project/list` 读取真实项目 ID，保存到普通任务；通过 `thread/start.projectId` 创建归属正确的对话，通过 `thread/metadata/update` 修复未归属的已有对话。
- 映射规则：显式选择的项目必须包含工作目录。只填目录时选择最深匹配的项目根目录；同级存在多个项目时要求明确选择。项目失效、目录不匹配、会话已移到其他项目时阻止发送。
- 历史修复：后台连接后，仅检查本面板普通任务已创建的空闲对话，补齐缺失的项目归属；保留已经明确分配的项目。不会读取并改写客户端全局 JSON 状态。
- 任务表单：编辑、复制、前置接续、会话接续保留项目 ID；切换项目不复用旧项目的对话；项目与会话列表的异步响应校验当前选择，避免覆盖切换后的状态。
- Windows 路径：统一比较大小写、混合分隔符及扩展路径前缀，严格区分同名前缀的不同文件夹。
- 督导移除：移除页面、接口、调度钩子、验收执行、纠偏、文件占用、脚本和 MCP 入口。磁盘上的旧档案保留，旧督导指令及其依赖不能自动派发；已经发送的桌面请求只按原编号恢复监控。
- 界面：编辑区获得更多宽度，任务列表独立滚动；宽编辑区分栏，窄屏单栏；来源列表适应客户端数量；移除遮挡字段的吸底保存栏，运行详情显示完整目录。

早期验证包括：主程序 136 项测试、MCP 8 项测试；真实客户端项目列表；隔离 Codex 数据目录内的新建项目归属、历史归属更新及数据库持久化，全程未发起模型推理；桌面与 390 像素窄屏的表单选择、保存、只读状态和横向溢出检查。

更新后台时保持队列暂停，核对原 WorkBuddy 请求编号、对话编号、监控检查点与运行记录总数；恢复的是同一请求的监控，没有重新发送任务。原督导档案与文件占用历史保持不变，旧接口返回 404。更新前的完整数据备份保存在 `test-scratch/before-backend-restart.json`。
