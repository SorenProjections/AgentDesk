# 豆包桌面端

在“Agent 接入”中选择“豆包桌面端”。支持定时、每天／每周重复、排队及前置任务完成后新建或续接聊天，回复会写入运行记录。可选择豆包自己的项目及项目中的已有对话；新建任务首次创建对话后，后续周期继续该对话。会话工作台同步客户端已加载的豆包对话，提供筛选和安排接续。暂不提供后台重启后的原请求监控或自主监督任务。

1. 等豆包当前任务结束，在托盘菜单中完全退出豆包。
2. 点击“启动桌面连接”。默认查找 `%LOCALAPPDATA%\Doubao\application\Doubao.exe`，也可设置环境变量 `DOUBAO_DESKTOP_BINARY` 为 exe 完整路径。
3. 打开已登录的主聊天界面，点击“检测连接”，再用“测试发送”验证真实回复。

启动参数为 `--remote-debugging-port=9338 --remote-debugging-address=127.0.0.1`。适配器验证端口属于豆包进程，并仅连接本机调试端口中的豆包聊天页面。不关闭已有豆包进程，不读取登录凭据。若客户端版本不支持调试端口或聊天界面标记，检测会显示未连接。

模型、项目资料和工具权限沿用豆包当前设置。豆包项目与面板里的本地项目目录分开：不会因为面板保存了本地路径就给豆包挂载目录或授予权限。聊天任务不要求本地项目目录，也不申请或检查该路径的文件占用；旧任务中保存的归档路径不参与执行。

项目和会话列表来自豆包客户端当前已经加载的侧栏，不宣称包含全部云端历史。列表缺少目标时，先在豆包展开项目或打开目标对话，再点击刷新。选择已有对话时保留其上下文；新建时使用所选项目的新对话入口，不指定项目则新建普通聊天。运行期间保持目标聊天界面打开，避免手动切换或发送其他消息。发送前检查对话编号、所属项目、既有消息和草稿，已有草稿或正在生成时停止发送，不覆盖内容。

同一豆包界面只执行一个面板任务。完成判定要求本次用户消息、回复操作栏、生成结束以及回复文本连续稳定；界面监控不能证明豆包工具的全部副作用成功。连接断开、切换对话、超时或发送结果不明确时标为“待核实”，不重发。点击面板停止仅停止监控，豆包中的生成需要在客户端停止。

实现参考了 [OpenCLI 的豆包桌面适配器](https://github.com/linxule/opencli/blob/main/src/clis/doubao-app/utils.ts)中公开的界面属性，并核对本机客户端资源；未依赖厂商承诺稳定的对话 API。客户端升级后应重新检测和测试发送。
