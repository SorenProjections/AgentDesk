# AgentDesk 使用指南

[返回项目首页](../README.md)

## 会话管理与完成提醒

- 自动同步 Codex、WorkBuddy 与 Antigravity 的本机原生会话，按运行中、需要处理、最近、已置顶及已收起筛选；支持按 Agent、项目、名称与备注搜索。
- 每个原生会话以“来源 + 原生编号”建立映射，关联本面板发送记录，支持独立名称、备注、置顶、关注提醒与收起。收起仍会提醒；关闭某个会话的提醒需要取消关注。映射操作不改动或删除原生对话。
- 完成、失败、停止、需要处理与断连提醒保存到本机收件箱，可逐条或全部标为已读。首次导入不推送历史结果；同一轮状态按编号去重，后台重启保留观察基线与未读结果。内部 Guardian review 会话自动过滤。
- Windows 系统通知默认开启，网页关闭后后台仍可提交通知。使用“测试系统提醒”验证；实际弹窗受 Windows 的 PowerShell 通知权限、勿扰设置影响。提交失败会在收件箱保留原因。后台停止、电脑睡眠或关机时不能持续观察。
- “学习 25 分钟”和“休息 60 分钟”暂缓系统弹窗，收件箱继续收集结果；结束时聚合推送未读结果，也可提前恢复提醒。

观察范围与证据：

| 来源 | 观察方式 | 边界 |
| --- | --- | --- |
| Codex | 只读 `state_*.sqlite` 与原生 JSONL 轮次事件 | 最近 250 条库记录及已关注记录；只有 `task_complete` 确认完成。独立 App Server 不用于推断其他客户端是否运行。外部权限等待缺少可靠持久事件时会显示运行或待核实，需原客户端处理。 |
| WorkBuddy 普通启动 | 只读 `workbuddy.db`、项目 JSONL 与本轮终态日志 | 最近 100 个本地会话、库中所有标记运行的会话及已关注记录。不需要重启或启用调试端口。`completed` 数据库状态还必须匹配本轮最终回复与终态日志；取消、旧回复或证据缺失不会当作成功。 |
| WorkBuddy 桌面桥 | 当前客户端 SDK 会话与请求 | 最近 60 个会话、已关注会话及列表标记运行的任务；子任务与后台工作结束后才确认。发送接续消息仍需桌面桥。 |
| Antigravity | 当前本机桌面服务中的 trajectories、步骤与回复 | 最近 60 个会话、已关注会话及列表中的运行任务；只显示当前服务返回的记录。服务返回零条不等于客户端所有历史对话均为空。 |
| CLI | 本面板发送与执行记录 | 不宣称能够发现其他程序启动的独立 CLI 会话。 |

后台目标每 5 秒观察一次，实际频率取决于本机接口响应时间。断开的桌面连接每 60 秒尝试重新检测，WorkBuddy 自动使用原生只读路径。连接失败和状态过期保留上次证据；Codex / WorkBuddy 超过 15 分钟无活动且没有终态证据时显示待核实，不误报完成。首次读取日志最多回看 8 MiB，超出可辨认范围时保守显示待核实。

点击会话可以打开 Codex 原生对话、查看已关联执行记录，或给已空闲且可发送的会话安排接续消息；发送前仍需填写并保存提示词。WorkBuddy 只读接入显示如何启用桌面桥，权限请求与追问在原客户端处理。

需要 Node.js 22.13 或更新版本；无需安装 npm 依赖。项目可以放在任意本地目录。

## 启动与停止

双击 `start.cmd`，或执行 `npm start`。面板地址：[http://127.0.0.1:43127](http://127.0.0.1:43127)。网页关闭后后台继续运行；再次启动会打开现有面板。

面板分为“会话工作台”“工作队列”“运行记录”“Agent 接入”“后台设置”五个页面。工作队列负责编辑和排序，运行记录集中查看回复与处理请求，Agent 接入管理桌面连接及可选 CLI，后台设置提供以下选项：

- **登录 Windows 后自动启动**：设置当前用户的启动项，登录后隐藏启动后台；未登录 Windows 时不会运行。
- **后台运行时保持电脑唤醒**：阻止空闲自动睡眠，屏幕可以关闭；手动睡眠、关机和断网仍会影响执行。
- **任务失败时暂停队列**：默认开启。失败或停止后，确认结果再恢复队列；状态不明时始终暂停。

自动启动和保持唤醒默认关闭。停止后台用面板按钮、`stop.cmd` 或 `npm stop`；正在运行时先停止对应运行。若启动项已开启，后台会在下次 Windows 登录时再次启动。

## 创建任务与接续消息

1. 点击“新建任务”，填写名称、Agent 和完整项目路径。
2. 选择新建对话，或继续已有对话。
3. 选择发送条件，写好消息并保存。

| 发送条件 | 执行方式 |
| --- | --- |
| 到指定时间发送 | 按北京时间 UTC+8 设置一次或多个时间，每个时间发送一次 |
| 加入队列，轮到时发送 | 保存后即可执行；等待当前运行结束，再按列表顺序发送 |
| 前置任务结束后发送 | 选择本面板中的任务，等待其当前运行，或保存后的下一次运行结束 |
| 桌面端当前任务结束后发送 | 选择 Antigravity 或 WorkBuddy 中正在运行的对话，确认该轮成功后发送 |

在已有任务下点击“添加接续”，即可创建下一条。可组成 A → B → C，并让后续任务在不同 Agent 中执行。沿用前置对话需要相同 Agent、相同文件夹及有效对话编号。跨 Agent 接续会执行后续预设消息，不会自动复制上一步的上下文或回复。

可在“等待哪次运行”中明确选择一次历史或当前运行。未指定时，已经结束的旧运行不会触发新消息。接续任务只发送一次，不会在前置任务的每次运行后重复。

默认只有前置任务成功才继续。可选择前置失败后仍继续，但全局“任务失败时暂停队列”若开启，仍需先恢复队列；状态不明时不会自动接续。

左侧上移、下移控制满足条件的任务的发送顺序；等待时间、依赖或编辑中的任务不会阻塞其他就绪任务。全局只运行一个任务。暂停队列影响后续发送，当前运行继续执行。要晚上开始，可给首条任务设定时间，再给后续任务设置前置依赖。

## 发送前编辑

打开任务后点击“编辑消息”，后台暂时锁住该任务。修改提示词、发送条件和目标对话后点击“保存修改”，释放编辑保护并使用新内容。“结束编辑”放弃未保存修改。

编辑保护每 20 秒续期，断开超过 90 秒后释放。关闭网页会释放保护，后续按最后保存的内容执行。需要长时间暂停时使用“暂停任务”或“暂停队列”。多个面板同时编辑时，后台拒绝覆盖其他面板的修改。

切换页面保留当前编辑草稿和编辑保护。打开其他任务或新建任务时，未保存的修改需要通过页面内弹窗确认后才会放弃；取消会保留草稿。窄屏下通过“返回队列”和“返回运行列表”切换详情与列表。

开始发送后不能修改该次运行；记录保留发送时的提示词。已发送的队列消息可复制成新任务。定时任务的未来时间仍可编辑。“立即运行一次”对定时任务是额外发送一次，保留预约时间；对排队或接续消息则执行其唯一一次发送，且必须满足发送条件。

## Agent 接入

**Codex** 使用本机 App Server，支持项目对话列表、上下文续接、权限请求和停止运行。模型和推理强度沿用本机配置，可单独指定。文件权限、网络和确认方式可在面板中设置。桌面端打开的对话可能需要重新打开才能显示新结果，避免其他客户端同时运行目标对话。

**Antigravity 桌面端** 连接当前用户正在运行的本机桌面服务，复用桌面登录账号，可读取真实对话列表、新建对话、续接和停止运行。打开 Antigravity 后点击“检测桌面连接”。模型默认使用桌面服务的默认值，也可填写桌面模型列表中的完整名称。服务默认值可能与界面当前选择不同。权限确认和追问在原客户端处理。

**WorkBuddy 桌面端** 通过仅监听本机的连接端口调用客户端已有的对话 SDK，复用桌面登录账号、本地对话与权限设置。首次使用需要等当前任务结束、完全退出 WorkBuddy，再点击面板中的“启动桌面连接”，然后检测连接。该入口以 `--remote-debugging-port=9337 --remote-debugging-address=127.0.0.1` 启动桌面程序；普通启动不一定带有该端口，以后需要桥接时也使用此入口。面板不会强制关闭正在运行的 WorkBuddy。当前支持本地对话；模型和权限沿用客户端配置。

两个桌面适配器依赖客户端当前版本的本机接口，属于本项目的兼容实现，未使用厂商承诺稳定的公共对话管理 API。客户端更新后应重新检测并验证。桌面接入与独立 CLI 在面板中分开选择。

**Antigravity CLI** 使用独立 `agy` 程序。面板按实际 CLI 帮助参数检测能力：结构化输出可记录新对话编号；只有文本输出时可新建运行、手填已有编号，但不能自动沿用刚创建的对话。模型和推理强度取决于实际 CLI 能力。

**WorkBuddy CLI** 使用桌面端自带的 `resources\app.asar.unpacked\cli\dist\codebuddy-headless.js`。设置 `CODEBUDDY_CONFIG_DIR` 指向 `.workbuddy`，仍可能要求独立登录。CLI 列表只显示本面板运行过的会话。

“检测连接”只验证程序和接口。“测试发送”发送一条仅回复测试文字的提示词，验证登录和真实返回；验证期间队列暂不发送新消息，结束后恢复原状态。上次验证结果保存在面板中，测试使用少量 Agent 额度。

WorkBuddy CLI 如提示登录，在 PowerShell 中执行：

```powershell
$env:CODEBUDDY_CONFIG_DIR = Join-Path $env:USERPROFILE '.workbuddy'
$workbuddyRoot = 'C:\path\to\WorkBuddy' # 替换为你的 WorkBuddy 安装目录
node (Join-Path $workbuddyRoot 'resources\app.asar.unpacked\cli\dist\codebuddy-headless.js')
# 在 CLI 中输入 /login，按提示完成登录
```

Antigravity CLI 通过交互运行 `agy` 登录；更新方式以所安装版本的帮助说明为准。登录或更新后，再点击“验证账号运行”。

两个 CLI 的文件、网络和命令权限遵循自身配置，Codex 权限选项不会应用到它们。面板不添加跳过所有权限的参数。无人值守前先配置所需权限；要求交互的步骤会等待处理或失败。最长运行或监控时间默认 120 分钟：CLI 超时停止进程，桌面适配器超时停止接续监控、保留原客户端任务；均标记待核实，不自动重发。

“桌面端当前任务结束后发送”可以等待直接在原客户端启动的运行。先启动桌面任务，在面板选择正在运行的对话并保存等待目标，再设置接续消息的 Agent、新建或已有对话和提示词。消息可跨 Agent 发送，但不会自动复制前一步的回复。监控绑定保存时的那一轮消息，不会用更早的历史回复或后来手动发送的新消息满足条件；子任务未结束、权限待处理、失败和中断都不会误判为成功。后台停止、客户端断开或等待目标发生变化后，需要核实，并在编辑时勾选“重新绑定此刻正在运行的任务”以恢复监控。

## 恢复、保存与验证

运行记录在发送前原子保存，防止重复发送。后台异常结束后，未确认完成的运行标记为“待核实”，相关任务和队列暂停。先核实对应对话，再决定如何继续；后台不会自动重发。

错过定时时间默认补跑，也可设置超过一分钟跳过。实际开始时间取决于之前任务的时长、电脑和网络状态。

| 文件 | 用途 |
| --- | --- |
| `launch.mjs`、`start.cmd`、`stop.cmd` | 启动与停止后台 |
| `server.mjs` | 本机 HTTP 与面板接口 |
| `lib/scheduler.mjs` | 队列、依赖、编辑保护与发送记录 |
| `lib/providers.mjs` | Antigravity、WorkBuddy CLI 与完成事件解析 |
| `lib/desktop.mjs` | Antigravity 本机桌面服务与 WorkBuddy 桌面 SDK 桥 |
| `lib/sessions.mjs` | 统一会话映射、轮次提醒去重、未读收件箱与安静时段 |
| `lib/native-codex.mjs`、`lib/native-workbuddy.mjs` | 原生会话库与轮次记录的只读观察 |
| `lib/codex.mjs` | Codex App Server |
| `lib/system.mjs`、`background.vbs` | 登录后启动与保持唤醒 |
| `lib/store.mjs` | 原子存储与旧版数据迁移 |
| `web/index.html`、`web/styles.css` | 五个页面的结构、统一样式与响应式布局 |
| `web/app.js`、`web/workspace.js` | 任务与运行交互、导航和列表/详情切换 |
| `web/api.js`、`web/providers-view.js` | 接口调用、提示与确认弹窗、Agent 接入组件 |
| `web/sessions-view.js` | 会话管理、来源覆盖、提醒与学习休息界面 |
| `data/tasks.json` | 本地任务、提示词、设置与运行输出 |
| `test/` | 自动化测试 |

旧版预约数据自动迁移，迁移后请使用新版后台。备份 `data` 时注意含有输入内容与运行输出。修改前端后刷新页面，修改后台后重启。

`npm test` 覆盖预约、队列串行、一次性接续、历史隔离、前置失败、编辑保护、冲突检测、循环依赖、重启恢复、跨 Agent 接续、真实子进程流解析、空回复、权限拒绝与桌面监控。桌面测试还检查错误步骤、子任务、消息身份、提交确认与实际完成的区别、重新绑定中断的监控，以及 WorkBuddy 的列表通道、分页、文件夹筛选与 SDK 错误。

环境变量：`CODEX_SCHEDULER_PORT`、`CODEX_SCHEDULER_DATA`、`CODEX_SCHEDULER_BINARY`、`ANTIGRAVITY_SCHEDULER_BINARY`、`WORKBUDDY_SCHEDULER_BINARY`、`WORKBUDDY_DESKTOP_BINARY`。CLI 路径也可在面板配置，仅接受可执行文件或 Node.js 入口，不经 shell 拼接。

接口参考：[OpenAI Codex App Server](https://learn.chatgpt.com/docs/app-server)、[Google Antigravity Headless](https://www.antigravity.google/docs/cli/headless/)、[腾讯 CodeBuddy CLI Headless](https://www.codebuddy.ai/docs/cli/headless)。
